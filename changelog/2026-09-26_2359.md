# Design pass: blueprint direction, IBM Plex, routing fixes

**2026-09-26 23:59**

Full UI pass implementing the "Direction A + C typography" proposal —
fab-drawing visual language, editorial typographic discipline. Plus the
routing and content fixes queued from the previous session.

`npm run build` and `npm run lint` pass. Not visually verified: the Chrome
extension was not connected, so nothing in here has been looked at in a
browser. Compiled CSS was inspected directly instead (see Verification).

## Design system

### Semantic color tokens
`src/index.css`

Replaced the untouched Tailwind `slate` palette with a token layer. Colors are
plain custom properties re-exported through `@theme inline`, so Tailwind emits
utilities (`bg-paper`, `text-ink`, `border-rule`) that track the active theme.

The practical effect: components no longer carry `dark:` variants at all. A
component asks for `text-ink` and the theme decides what that means. Every
`text-slate-900 dark:text-slate-100` pair in the codebase collapsed to one
class.

Palette is a fab-drawing reference — warm paper stock, near-black ink,
hairline rules, copper (`#a4622a` light / `#d2934f` dark) as the single accent.

### Typography
IBM Plex Sans + IBM Plex Mono, loaded from Google Fonts with preconnect.

Chosen over Inter specifically because Inter is on every portfolio in
existence. Plex is free, designed for technical documentation, and the
sans/mono pair is drawn to work together.

Mono is used structurally, not decoratively: section labels, metadata, tags,
role/location, nav, footer, all buttons. Sans carries headings and prose. The
split is what produces the drawing-sheet feel.

### Dark mode toggle
`src/components/ThemeToggle.tsx`, inline script in `index.html`

Every component already had `dark:` variants but users had no way to reach
them — it followed the OS and nothing else. Now a `data-theme` attribute with
localStorage persistence, defaulting to the OS preference.

The theme is applied by a synchronous inline script in `<head>` before first
paint. Deferring it causes a light-mode flash for dark-mode users.
`localStorage` access is wrapped in try/catch — it throws in Safari private
mode.

### New primitives
- `SectionHeading` — sheet number, tracked mono label, hairline rule to the
  margin. Sections are numbered `01 / ABOUT`, `02 / PROJECTS`, `03 / CONTACT`.
- `.corner-ticks` — registration marks on two opposing corners. Two rather
  than four: four reads as decoration, two reads as a frame.
- `grid-paper` utility — faint 32px engineering grid, used on the hero and
  projects sections to alternate texture.

## Routing

### Header nav fixed
`src/components/Header.tsx`, `src/components/Layout.tsx`

The nav used bare `#about` / `#projects` / `#contact` fragments, which were
dead links on every route except `/` because those sections only exist on the
home page.

Now `/#about` etc. via React Router `Link`. React Router does not act on the
hash by itself, so `Layout` has an effect that scrolls to `location.hash` on
change and to the top when there is no hash.

### Quant and ML routes removed
Subsumed by other projects. Removed from the drawer, from `App.tsx`, and the
page files deleted (`src/pages/QuantTools.tsx`, `src/pages/MLTools.tsx`).

The drawer is down to two entries — Portfolio and Blog. Worth deciding whether
a full-screen overlay drawer is still the right control for two links, or
whether Blog should just move into the header nav.

### 404 route added
`src/pages/NotFound.tsx`

There was no catch-all. Combined with SPA fallback on Workers, every mistyped
URL returned 200 and rendered an empty page.

Copy is a placeholder marked `PLACEHOLDER COPY` in the file — the route and
layout needed to exist, the joke is yours to write.

### Project detail pages
`src/pages/ProjectDetail.tsx`, route `/projects/:slug`

`slug` existed on every project and was used only as a React key. Now it
routes. An unknown slug renders `NotFound` rather than an empty page.

This was a prerequisite for clamping card descriptions — clamping without
somewhere to read the full text would have hidden content with no way back to
it.

### Cards
`src/components/ProjectCard.tsx`

Descriptions are `line-clamp-3` with a "Read more" link to the detail page,
which fixes the uneven card heights and the wall of 90-word `text-sm` copy in
a 350px box. The dot-grid fallback introduced last session now also sits
behind `object-contain` screenshots, so letterbox bars read as matting rather
than dead space.

### Resume viewer
`src/components/ResumeViewer.tsx`

The 70vh PDF iframe is now `hidden md:block`. It was unusable on a phone and
unreliable in iOS Safari; small screens get the Open / Download / Transcripts
links instead.

## Verification

No browser. Compiled CSS was checked directly for the things most likely to
fail silently:

- All token utilities emitted: `text-ink`, `bg-paper`, `border-rule`,
  `text-accent`, `bg-surface`, `text-ink-muted`
- Custom utilities emitted: `grid-paper`, `corner-ticks`, `line-clamp-3`
- IBM Plex present in both the sans and mono stacks
- `bg-paper/85` resolves to `color-mix(in oklab, var(--paper) 85%, transparent)`
  with a flat fallback rule
- Dark-mode cascade ordering confirmed correct: light defaults, then the
  `prefers-color-scheme` block guarded by `:not([data-theme="light"])`, then the
  explicit `[data-theme="dark"]` block declared last so a manual choice wins
  over the OS
